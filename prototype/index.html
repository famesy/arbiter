      How agents connect

      Each Claude Code or Codex session talks to arbiter as an MCP server. The Agent tool calls tab shows these calls as they happen. While an agent is in line, its call to acquire_board simply doesn't return yet, so it waits its turn without any special logic.

      list_boards()                          boards, targets, who holds each, power state
acquire_board(target, reason)          lease id once granted; blocks while in line
detect_console(lease, artifact)        RTT or UART: .config, then ELF symbol, then probe scan
flash(lease, artifact)                 west flash with the board's runner
serial_expect(lease, pattern, timeout) reads the console until a pattern or timeout
serial_write(lease, line)              sends a shell command to the board
debug(lease, gdb_commands)             one-shot GDB batch through the probe
power(lease, state)                    on, off or cycle, through the PPK2 or external supply
set_voltage(lease, mV)                 supply output voltage
measure_current(lease, window_ms)      average and peak current over a window
release_board(lease)                   hands the board to whoever is next

      Power control and current measurement work with a Nordic PPK2 in source meter mode (like the ppk2-api-python library) or any bench supply that speaks SCPI. A board on plain USB power can still be flashed, but not power cycled or measured.

      When you take a board over, the holder's next call returns preempted and waits until you give it back, so the agent pauses instead of failing.
